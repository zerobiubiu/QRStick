## 规范

- **按类型分目录**：`architecture/`（架构说明）、`decisions/`（关键决策）、`changes/`（变更记录）；每个目录一份 `README.md` 作本目录索引。
- **编号只做目录内局部递增**（`0001-`、`0002-`），不复用、不跳号；持续维护的现状文档用固定名称。
- **元数据**写在文首：状态、影响范围、前置文档、替代文档、生效版本。
- **治理分类**：区分「现状文档」（描述系统当前有效状态，可随演进更新）与「不可变变更文档」（一次已执行变更的定稿记录，后续变化另建文档并标注替代关系）。

## 要求

- 改动源码（功能、修复、优化、模块增删）必须随行写 `docs/changes/`，内容含：背景、方案、实施（改动文件清单）、执行验证记录、后续验证建议；小改并入同一份并说明合并了哪些变更。
- 新增文档必须回本文件补索引。
- 定期归并：同类变更积累到一定数量或一个阶段结束时，按主题浓缩，防止文档膨胀。
