## 背景（先取证，再动手）

按 `/impeccable harden` 的口径（极端输入 / 错误路径 / 并发 / 空状态 / 大数据）做了一轮取证：**两份独立只读审计**（渲染与导出链路、输入与状态链路，逐条带 `文件:行号` 证据）＋ **5173 上的真实浏览器探测**（含 5000 字符、6000 字标题、2000mm×1:10、二进制改名 CSV、导出中连按 Alt+1、隐私模式存储等）。

确认的真实缺陷，按危害排序（前三条是「用户会拿到废件或根本没有界面」级别）：

| # | 问题 | 取证 |
| --- | --- | --- |
| 1 | **超容量内容把整个应用打白**：二维码四级都装不下时 `createQrMatrix` 重抛，异常冒到 React 渲染里整棵树卸载 | 实测 5000 字符 → 页面按钮数 39 → **0**、canvas 0，只能手动刷新；报错是 qrcode 英文原文 |
| 2 | **画布分配失败被当成成功**：`renderLabel` 直接给 `canvas.width/height` 赋值，`if (ctx)` 里才绘制；分配失败时整段绘制静默跳过、函数照常返回 | 2000×2000mm @600DPI = **2232 兆像素**（浏览器上限约 268），`validateLabel` 只在 >60 兆像素给一句 warn，导出照走 |
| 3 | **一页坏拖垮整批**：`renderLabel` 在逐页 try/catch **之前**执行（`runImage` 的 `targets.map`、`run` 的逐页循环、`export.addPage` 的 `toDataURL` 都没有隔离） | 一行超容量数据会让整批 PNG/PDF/Word/ZIP/拼接全部失败，已渲染好的页一起丢 |
| 4 | **自定义长宽比的派生值不钳制**：`applyRatio` 只做 `Math.round(width*ratio*10)/10` | 宽度 2000mm（数字框上限）配长宽比 1:10 → 高度 **20000mm**，越过同字段上限 10 倍 |
| 5 | **持久化写入失败静默**：`usePersisted` 的 catch 是空块；界面却承诺「改动自动保存」 | 隐私模式 / 配额满 / 超大 rows 时用户以为已保存；四个键各自写，可能出现 rows 失败而 config 已写的混合状态 |
| 6 | **快捷键绕过导出锁**：`useAppShortcuts` 直接 `void onExport(action)`，只有按钮吃 `disabled={busy}` | 导出中连按 Alt+1 会并发起多次完整导出并互相覆盖状态行（实测探针记录到两次导出相位） |
| 7 | **残留选中行静默缩小导出范围**：导入/清空只 `setRows/setBatch`，从不重置 `selectedIds` | 已有勾选时导入新数据，导出侧按 `picked.length ? picked : rows` 取值 → 只导出同号那几行，顶栏却写「出 选中的 N 张」 |
| 8 | **导入无覆盖确认、0 行当成功**：有数据时直接覆盖（「清空数据」反倒要确认框）；空文件/仅表头解析出 0 行仍 apply | 行被清空、batch 却设成文件名，头部显示「未导入」而下面写着新文件名 |
| 9 | **缩略图常驻内存 + 整批同步重渲**：`IntersectionObserver` 一旦相交 `visible` 永不回收；任何参数改动让最多 200 张缩略图在同一提交里同步 `renderLabel` | A4 竖版单张约 3.3MB RGBA，200 张累计数百 MB；拖滑杆整段卡顿 |
| 10 | **假纠错等级**：色标条与读数条印的是**请求**等级，码面用的是回退后的等级；`RenderResult.downgraded` 产出后全项目无人消费 | 内容较长时贴纸自证信息失真，文件头「如实上报」的纪律落空 |
| 11 | **超长标题把二维码挤成废码**：`wrapTitleLines` 无行数上限，只有一条 error 文案 | 776 字标题 → 36 行 → 二维码被压到**外框 1.2mm / 1px 模块**，导出即废件 |
| 12 | 其余：导入非白名单扩展名（.xlsm/.ods/无扩展名/二进制改名 .csv）静默入库；提醒里的行号比 Excel 少一行；`sniffDelimiter` 为看 8 行先 split 全文；滑杆量程窄于数字框（80mm 一拖就被压回 60）；批量模式 0 行仍可导出单张；`main.tsx` 没有 ErrorBoundary（#1 的放大因素） |

**明确不做**（避免把加固做成改版）：不动滑杆「常用区间」的既有设计（`DESIGN.md` 记为刻意取舍，需要产品决策）；不给导入加体积硬上限（要不要分片导入是产品问题，本轮只做嗅探截断与格式拒绝）；不把 config/view/presets 的写入失败也搬上界面（rows 是唯一会因体积爆配额的那一份）。

## 方案

| 项 | 做法 |
| --- | --- |
| 渲染核 **never-throw** | `renderLabel` 返回 `failure: null \| 'qr_overflow' \| 'canvas_unavailable'`：占位框二维码按 `qr_overflow` 报出，画布分配失败（`getContext` 为 null 或尺寸被浏览器夹小）按 `canvas_unavailable` 报出；绘制过程再包一层 try/catch，绝不让异常冒进 React |
| 容量预检 | `ECL_BYTE_CAPACITY`（版本 40 字节模式：L 2953 / M 2331 / Q 1663 / H 1273）＋ `validateLabel` 报「内容 N 字节超出二维码容量（纠错 X 最多 Y 字节）」，不再靠抛异常试探；`createQrMatrix` 四级全失败返回 `null` → 画占位框 |
| 画布上限 | `MAX_RENDER_MEGAPIXELS = 100`（A4@600 约 35 兆，A4@1200 约 139 兆）按 error 拦下，`CANVAS_WARN_MEGAPIXELS = 60` 仍是提醒 |
| 标题上限 | 标题最多占版心高度 **60%**（`TITLE_MAX_HEIGHT_SHARE`），超出的行不印并把裁掉的行数写进体检；二维码从此至少留四成高度 |
| 折行 | 按**字素簇**断行（ZWJ 组合 emoji / 变体选择符 / 组合附加符不再被切散），宽度改按字素簇前缀累加——万字号标题从 O(n²) 变成线性 |
| 导出隔离 | 逐页 `toExportPage/toWordPage` 失败即返回 `null`，逐页 try/catch 跳过并计数；`PdfBuilder.addPage` 返回 boolean（编码失败只跳过该页）；ZIP 加 `ZIP_MAX_BYTES = 512MB` 上限、`zipSync` 包 try/catch、清单条目改为成功后 push |
| 失败口径 | 新增 `src/lib/failures.ts`（`renderFailureText / tallyFailure / failureCount / summarizeFailures`），文档导出与图片导出共用；`ExportOutcome` 与 `ImageExportOutcome` 统一带 `failed: number` + `failureReasons: string[]`（去重、最多 3 条人话） |
| 导出锁 | `useExportActions` 内加 in-flight ref（覆盖按钮与快捷键两条路），`useAppShortcuts` 增加 `enabled`（`!busy && !batchEmpty`） |
| 失效键 | 「已导出」记录改为 `configKey + rows 指纹`（FNV-1a 定长指纹，不对大表做全量 stringify）；批量数据一改，记录立刻退回 idle |
| 选中与导入 | `labelStore.setRows` 丢弃越界选中，导入/清空显式清空选中；已有数据时导入走同一个确认框（写明替换条数与来源）；0 行当错误报出并**保留原数据**；非白名单扩展名与二进制改名显式拒绝；`sniffDelimiter` 只看前 64KB；提醒改报文件物理行号，超过 4 条可展开 |
| 存储可见 | `usePersisted` 暴露 `PersistStatus`（区分配额满 / 隐私模式 / 其它），rows 这份键 400ms 去抖 + 卸载时 flush；数据源区就地提示「本机存储写入失败：本次改动不会保留（原因）」 |
| 纠错真相 | `layout.actualErrorCorrectionLevel` 成为唯一读数来源：色标条、PressSheet 读数条（新增「纠错」一格，回退时写「L（请求 H）」）、状态行摘要一致 |
| 兜底 | `main.tsx` 挂极简 ErrorBoundary（工单风格 + 「重新载入」）；批量预览离屏即回收画布、rAF 每帧最多出 4 张、失败格不挂空白画布 |

**已知限制与未做项**（诚实记录）：

- 滑杆量程与数字框不一致（字号 160/400、边长 300/1000、页边距 60/80）保留：`DESIGN.md` 记为刻意的「常用区间」，拖动会把越界值压回量程——如需改，应作为产品决策单独处理。
- 导入仍无体积硬上限（几十 MB 的 CSV/XLSX 会占用主线程），本轮只做嗅探截断与格式拒绝。
- `config` / `view` / `presets` 三份键的写入失败仍未上屏（rows 是唯一会因体积爆配额的一份）。
- A4@1200 DPI（139 兆像素）按新上限被拦在导出之外；600 DPI 以内不受影响。
- ErrorBoundary 已挂但未人为触发（它只在渲染期异常时接管，属兜底而非路径）。
- `DESIGN.md` 与旧文档里仍引用其它未改动文件的旧行号（本轮只校正了被改到的段落）。

## 后续验证建议

1. 大表压力：导入 5000 行后拖字号/DPI 滑杆，确认缩略图只在每帧出 4 张、滚出屏后内存回落（可用 `performance.memory` 或 DevTools 内存快照对比）。
2. 批量导出隔离：构造 10 行「好坏交替」数据，分别跑逐张/打包/拼接三种模式，核对状态行的「已跳过 N 张」与实际落盘张数一致。
3. 份额边界：把页边距调到 12→0、二维码边长调到 >版心，确认体检提示与导出行为（空间受限时二维码被压到多小才该拒绝出片，是下一个可决策点）。
4. 追平行号：下次跑 `/impeccable document`（或 doctor）时顺带刷新 `DESIGN.md` 里的源码行号引用。
