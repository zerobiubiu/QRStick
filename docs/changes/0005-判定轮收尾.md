## 背景

评审的判定轮（第二轮）结论为 **ship**：6 条必修项全部判 resolved。同时给出 3 条不阻断发布但应当收掉的项，以及 1 个取证缺口（批量面无画面证据）。

## 方案

| 项 | 处理 |
| --- | --- |
| `src/lib/types.ts` 的 `MarksConfig` 注释仍写「默认全关」，与 `labelStore` 的 `cropMarks: true` 相反 | 注释改为「默认只开四角裁切标记（会被印进导出件），色标条与边距线按需开」 |
| `StateLine` 固定输出「· 导出失败：…」，而 `App` 的非 Error 兜底句本身以「导出失败」开头 → 会渲染成「导出失败：导出失败，…」 | `App` 兜底句改为「无法写入下载文件，请检查浏览器的下载权限」 |
| `docs/decisions/0001` 的后果清单把「出血」列为必须做成真功能的印刷标记，而 0004 已决定不实现 | 该处改为「裁切 / 边距 / 读数」并注明出血不实现的理由与指向 0004 |
| 批量面无画面证据（评审点名的唯一取证缺口） | 补 `.impeccable/review/batch.png`：1440×900、40 行、合成滚轮与 scroll 事件后抓取，表头显示 `第 4–37 条 / 共 40 条`，右侧印张预览带四角裁切标记 |
