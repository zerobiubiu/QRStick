## 背景（先量漂移，再动手）

`/impeccable document` 的扫描结论：DESIGN.md 437 行、八节结构完整、令牌值本身没漂（颜色 21/21、字号 12/12 都能在代码里找到），但**事实层已经不可信**：

| 事实 | 证据 |
| --- | --- |
| 行号引用大面积失准 | DESIGN.md 里有 **174 处** `src/…:行号` 引用（只算 .ts/.tsx）＋ 12 处 CSS 引用。抽样多处对不上；按符号自动重锚的干跑里，61 条能唯一锚定的只有 **7 条**与原值一致，其余 113 条连唯一锚点都没有 |
| 有一处死链 | 12 处引用指向 `src/components/BatchGrid.tsx`——该文件在 0009/0012 后已改名 `BatchTable.tsx` |
| 侧车停在旧时代 | `.impeccable/design.json` 的组件清单里没有 0013 之后的新组件（首访上手条），叙事层也没有与 DESIGN.md 同步 |

根因不是「某次改漏了」，而是**行号引用在这个项目里本质不可维护**：0012 的结构重构、0013 的加固、0014 的按需加载、0015 的引导条，每一轮都会让上一条描述的行号偏移。

## 方案

| 项 | 做法 |
| --- | --- |
| 引用形式 | **只写文件与符号，不写行号**（`src/render.ts` 的 `renderLabel` 这样引）。行号会漂、符号不会，查证时 grep 符号即可；在 DESIGN.md 开头写明这条读法。186 处引用统一转换，`BatchGrid.tsx` → `BatchTable.tsx` |
| 令牌对表 | 用「全 `src/` + 去空白」的对表脚本核对 frontmatter 与代码：颜色 **21/21**、字号 **12/12** 命中；组件 padding/height 的 11 处「未命中」是 `0` vs `0px`、`sx` 缩写（`px: 2, py: 1` 等价 `8px 16px`）的**表示差异**，不是设计漂移（impeccable 探测器同为 0 发现） |
| 侧车重生 | `generatedAt` 更新；补「首访上手条 OnboardStrip」组件（自包含 html/css、`ds-` 前缀、含 hover/focus、不加 reset）；`narrative` 全部从 DESIGN.md **原样搬**（北星 / Overview / 6 条 Key Characteristics / **17 条律** / 10 Do / 13 Don't）——不改写措辞 |
| 架构现状文档 | `docs/architecture/0001` 补齐 0013/0014 的事实：渲染核 never-throw 与 `RenderResult.failure` 契约、两道尺寸闸门（二维码容量预检、100 兆像素上限）、导出器按需加载、预览按显示像素渲染；元数据改成「随系统演进」并标注修订来源，已知取舍与验证建议同步补两条 |

**明确不做**：不动叙事层（北星「印刷工单与印张」、色彩命名、各条例律保持 0001 决策的定稿措辞）；不动设计本身（本轮**零源码改动**）；不做整份重写（会丢掉探测器的对表依据与已固化的措辞）。

**一处对用户选择的有意偏离**：你选的是「174 处行号按符号重新锚定」，但干跑证明自动锚定不可靠（61 条里只 7 条还原正确）。继续做下去只剩人工逐条核对 174 处、而且下次改动又会全漂。所以改成**统一去掉行号**这条更稳的形式——信息量不减（文件 + 符号仍可 grep 校验），且这类漂移从此不再产生。

**已知限制**：

- 行号不再出现：要精确定位请用符号 grep（这是有意为之的取舍，见上文）。
- 侧车的组件快照（html/css）仍是**手写翻译**而不是从代码生成；改组件时需要同步（已在本轮把首访条补上）。
- `DESIGN.md` 的组件 padding/height 与代码的 `sx` 写法之间存在表示差异（值一致），对表脚本无法自动断言，需要人工抽查。
- 自动重锚探针（按符号 / 按字面量两版）已证明不可靠，脚本本身没有保留价值，留在仓库外等待清理。

## 后续验证建议

1. 下次改动组件时顺手在两处各写一条：`DESIGN.md` 的 Components 与 `.impeccable/design.json` 的 `components[]`（新组件尤其容易只补一处）。
2. 想知道「设计是否又漂了」，跑 `impeccable detect --json <改动文件>`（零发现即无漂移），不要靠肉眼对行号。
3. 侧车的手写 html/css 建议每两三个版本对一次：把面板里渲染出来的样子与真实界面并排看一遍，最容易发现配色/圆角/内边距的细微分叉。
4. 若将来要给 DESIGN.md 引入自动校验，优先校验「符号是否仍存在」（`grep 符号 文件`）而不是行号。
