## 背景（先分析，再动手）

以 AOCI 索引（62 条，含每个模块的职责/关系/约束）加静态核对作为地图，逐项取证后确认的真实问题：

| # | 问题 | 证据 |
| --- | --- | --- |
| 1 | **同一权威常量两处维护** | `PressSheet.tsx` 的 `STAGE_MAX_PX = 1800` 与 `lib/preview.ts` 的 `PREVIEW_MAX_PX = 1800` 各写一份，且 PressSheet 把 `previewScaleFor` 的公式又抄了一遍 |
| 2 | **同一业务规则两种语义** | 「行 → 配置」有三份写法：导出走 `lib/batch.ts#buildBatch`（`structuredClone` 深拷贝）、批量预览走 `BatchPreviewGrid` 内的私有 `buildRowConfig`（浅拷贝 + 新 title，与其余行**共享 page/qr/marks 子对象**）、App 的单张预览又抄一遍 |
| 3 | **巨型组件** | `Docket.tsx` 925 行：字段原语、五段参数、预设文件 IO（Blob / FileReader / input）全在一个组件里 |
| 4 | **UI 与编排/副作用混杂** | `App.tsx` 387 行：布局之外还含导出编排（try/catch + 进度回填 + 记录状态机）、window 键盘监听、指针拖拽的分栏实现、双份 localStorage 键名 |
| 5 | **状态与数据访问混杂** | `labelStore.ts` 505 行：状态动作之外还含 4 个键名、5 个读取兜底函数、4 段各自 `try/catch` 的写入 effect；`loadRows()` 被调用两次（同一份 JSON 解析两遍） |

依赖方向经核对**本来是干净的**（`lib/`、`export/` 不反向依赖组件或状态，无环），所以问题集中在「重复权威、巨型组件、职责混杂」，而不是分层错位。

**明确不做**（避免为重构而重构）：不拆 `lib/render.ts`（446 行，但它是刻意内聚的渲染核，拆开会把「毫米→像素→文件」的唯一链路打散）；不动「组件接收 store」这一既有协作约定；不引入通用表单框架或全局事件总线。

## 方案

| 项 | 做法 |
| --- | --- |
| 权威单一来源 | 预览上限只留 `lib/preview.ts` 一处；PressSheet 改用 `previewScaleFor(layout, PREVIEW_MAX_PX)` |
| 规则单一实现 | `lib/batch.ts` 导出 `buildRowConfig`（深拷贝），`buildBatch` 由它 map 得到；批量预览、App 预览、导出三处全部改走它 |
| 组件原子化 | `Docket.tsx` 只留外壳（数据源 + 段拼装 + 体检底栏 + 恢复默认，104 行）；字段原语 `docket/fields.tsx`；五段各自成组件 `docket/{Preset,Paper,Title,Qr,Export}Section.tsx`，每段只收自己那部分配置与 patch 回调 |
| 编排与副作用分离 | `state/useExportActions.ts`（导出编排 + 记录状态机 + 「参数一改就不算已导出」）、`lib/useAppShortcuts.ts`（热键 window 监听 + 输入框不抢键）、`lib/useSplitDrag.ts`（指针拖拽 + 光标锁定 + 解绑） |
| 状态形状与存储分离 | `state/types.ts` 收敛状态形状与常量；`state/persistence.ts` 成为**全项目唯一碰 localStorage 的地方**（四键、默认值、读取兜底、`usePersisted` 写入 hook、`loadInitialState` 一次读齐） |
| 依赖方向 | 预设文件 hook 从 `lib/` 移到 `state/`（它依赖状态形状），避免 `lib → state` 反向依赖；`labelStore` 不再包含存储代码 |
