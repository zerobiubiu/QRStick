## 背景

对 0.1.0 跑了一次完整设计评审（dual-agent：设计评审 + 探测器/浏览器取证；快照见 `.impeccable/critique/`）。评分 **29/40（Good）**，特异性判定「为这个产品做的，但深度压在单张主路径上」。4 条 P1 + 1 条 P2 + 4 条 advisory，用户选择「先修真相链与提醒」且「全部做完」。

## 方案（逐条对账）

| # | 评审发现 | 修法 |
| --- | --- | --- |
| P1-1 | 预览的二维码比出片大 3.27mm：取整发生在缩放**之后**（导出 24px/模块 = 58.93mm，预览 13px/模块 = 62.20mm），屏幕量到的 mm 与读数条、与印出来的三者互相打架 | 二维码的模块取整只在**导出网格**上做一次（`exportDpi` 固定为 `config.page.dpi`），预览把这张满 DPI 位图按毫米尺寸等比 `drawImage` 缩放；`LabelLayout` 明确区分 `qrExportSidePx`（导出网格）与 `qrSidePx`（预览绘制），并新增 `qrActualMm` 供读数与校验 |
| P1-2 | 默认配置就亮「1 警」，原因还是误诊（整数像素取整被写成「可用空间不足」），且提醒藏在滚动区 1426px 处 | 把「取整造成的微小缩短」（正常，读数已反映真实 mm，不再报警）与「被版心/剩余高度真的限住」（`spaceLimited`，才报）分开；体检从滚动区移入工单**常驻底栏**；状态行的虚线态直接带上原因文案（`reason`） |
| P1-3 | 窄屏批量下印张盖住工单参数行并截获点击：栅格两行各算成 343.75px，而印张列需要 744px | 窄屏栅格行改 `max-content max-content`（按内容高度设行，不再等分容器高度）；批量列已带固定高度与 `flex: 0 0 auto` |
| P1-4 | 「模块」单位后缀折成两行（元素盒 12×32px），数值格宽度按字段硬编码 82/84/92；13px 下浏览器数字箭头与点零糊成「6Ø」 | 单位后缀 `whiteSpace: nowrap`；数值格宽度收敛为两档规则（带单位 96 / 不带单位 76）；CSS 去掉数字框的上下箭头 |
| P2-1 | 静默失败与命名分叉：非法长宽比静默丢弃、越界静默裁剪、批量下「标题内容」未标注被 CSV 覆盖、折叠按钮把二维码参数挂在「规格」名下、同屏两个「数据」 | 非法比例就地报错并给出可抄的写法；越界显示「已收到 X，按上限 Y 生效」；「标题内容」补批量提示；折叠按钮改「更多二维码规格（静默区）」；数据源段改「批量数据源」 |
| 附加 | 线型词汇对读屏不可见；导出后改参数仍挂「已导出」 | 状态行加 `role="status" aria-live="polite"` 与四种线型的 tooltip 图例；导出记录带配置指纹，参数一变即回「已生效」 |
| P3 | 探测器 4 条 advisory（h1 20px / h2 17px 偏离字阶；两处 `#000` 不在令牌表） | 删掉未消费的 h1/h2（h3 留在字阶内）与无人使用的 `MuiDivider` 覆盖；`#000` 提升为命名令牌 `INK_DEEP` 并写进 `DESIGN.md` 与 `.impeccable/design.json` |
