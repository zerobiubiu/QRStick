# 0010 · 批量预览统一为 PressSheet：修溢出、可调尺寸、网格交互

- 状态：已执行
- 影响范围：`src/components/PressSheet.tsx`、`src/components/BatchPreviewGrid.tsx`、`src/state/labelStore.ts`、`src/lib/types.ts`、`src/App.tsx`
- 前置文档：[0009-图片工作台导出与批量编辑.md](0009-图片工作台导出与批量编辑.md)
- 生效版本：**0.5.0**（预览统一 + 缩放/列数控制 → minor）

## 背景

批量模式的单张预览当时是**另一套实现**：`BatchPreviewGrid` 里的 `Tile`（缩略图按 `THUMB_MAX_PX=760` 渲染）外加一层写死 `aspectRatio: '210 / 297'` 的包裹盒与标题行。与单张制作模式的 `PressSheet`（按台面测量适应、刻度尺、套准十字、六格读数条、`STAGE_MAX_PX=1800` 缩放）在组件、缩放、容器与信息上都不一致；包裹盒的比例与真实印张无关（60×40 贴纸时会留出与纸面无关的形状），也**没有尺寸可调**。

## 根因（结构上读出来的，不靠 `overflow: hidden` 掩盖）

1. **两套预览**：批量单张走 `Tile`，单张制作走 `PressSheet` → 组件、缩放档位、容器策略、读数三处都不同源。
2. **写死比例 + 嵌套比例**：外层包裹盒固定 A4 纵比（0.707），内层 `Tile` 又按行配置算比例，再加一行标题 → 外层盒子的高度由比例决定、内容却由内层决定，二者无关时就是死区或溢出。
3. **没有尺寸控制**：预览区只能靠拖分栏改宽度，没有缩放；放大与「看得全」之间没有出口。

## 方案

| 项 | 做法 |
| --- | --- |
| 统一预览组件 | 批量「单张突出」直接渲染 **`PressSheet` 本体**（`config` 换成当前选中行），单张制作模式同一个组件 → 组件、缩放、读数条、刻度尺、套准十字全部一致，不存在第二套实现 |
| 尺寸可调 | `PressSheet` 新增缩放：**适应 / ×1.5 / ×2 / ×3**（相对「适应窗口」的倍数），读数条右侧给出 `N px/mm` 实时读数；缩放值存在 store，两个模式共享同一档 |
| 放大不裁切 | 缩放 > 1 时台面 `placeContent: start` + `overflow: auto`：只在预览区内滚动，纸面整张都能看到，**整页不滚** |
| 不变形 | 画布一律 `object-fit: contain`；网格媒体框按**此行标签自身**的宽高比；网格列用 `minmax(0, 1fr)` 防止内容撑破 |
| 双击进单张 | 缩略图 `onDoubleClick` → 选中该行 + 切到单张突出（打开的就是双击那一张）；单击仍是选中 |
| 返回保位置 | 网格滚动位置存在组件内的 ref（跨排布切换存活），重新挂载时恢复到原位；选中行、列数、缩放、分栏比例都在 store |
| 网格布局可调 | 新增**列数**控制（自动 / 2 / 3 / 4 / 5）：自动按可用宽度 `auto-fill minmax(148px,1fr)`，固定列数用 `repeat(N, minmax(0,1fr))` |
| 键盘可达 | 缩略图是 `role="button"` + `tabIndex=0`，Enter/Space 选中，`aria-label` 标明「第 N 行预览（当前）」 |

- 已知限制：
  - 缩放档位到 ×3（对应约 12 px/mm 上限）；网格缩略图仍按 `THUMB_MAX_PX=760` 渲染，要看细节用「单张突出」+ 放大。
  - 列数只给 自动 / 2 / 3 / 4 / 5；极窄屏下固定 5 列会把缩略图压得很小（此时选「自动」更合适）。
  - 我之前一次「溢出」取证的探针取错了元素（抓到的是左侧工单的正常滚动区，`709 → 1921`），本轮已按预览区自己重测：修后为 `739 → 739`。前一版包裹盒的写死比例属结构性缺陷（读代码可得），但当时那条「1212px 死区」的量化结论不成立，特此更正。
  - `DESIGN.md` / `.impeccable/design.json` 仍落后于代码（缩放控件、列数控件、可编辑批量表等未进记录）。
