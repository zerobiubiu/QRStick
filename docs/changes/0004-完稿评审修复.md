# 0004 · 完稿评审修复

- 状态：已执行
- 影响范围：`src/App.tsx`、`src/components/{PressSheet,Docket,BatchGrid,StateLine}.tsx`、`src/theme.ts`、`src/state/labelStore.ts`、`PRODUCT.md`
- 前置文档：[0003-窄屏布局与测量兜底.md](0003-窄屏布局与测量兜底.md)
- 生效版本：0.1.0（未发布前的同版本修复）

## 背景

按 impeccable 的完稿评审流程，对 0.1.0 做了一次独立评审（code-led 构建，无 comp，评方向契约 + 工艺底线 + 机制正确性），处置结论是 **fix**，给出 6 条可被当前证据钉住的必修项。评审同时确认：方向世界与首屏主面成立（台面色 #f4f4f2、纸 #ffffff、毫米刻度尺按 2.53 px/mm 现算且逐个读数吻合、四色套准十字 17px、联单字段列 96px、导出三词到位），窄屏塌陷问题已在上一次修复中消失。

## 方案（逐条对账）

| # | 评审发现 | 修法 |
| --- | --- | --- |
| 1 | 台面按 border box 量、按内容框摆印张，多算 44px 内边距；窗口高瘦时纸面溢出被 `overflow:hidden` 裁掉，毫米尺只剩约 2px | `useMeasuredBox` 改为量内容框（`clientWidth` 减去计算后的内边距），并给内层栅格加 `maxWidth/maxHeight: 100%`，让任何量测误差都表现为整体缩小而不是裁切 |
| 2 | 状态仍有两处靠颜色（体检 error 文本、导出失败文本），且主题里有 warning/success 两档死色、`#c0143c` 不在锁定五色内 | 两处文本改回 `text.primary`（级别由双线/虚线承担）；主题只保留 `error: { main: INK }` 以满足调色板形状，删掉 warning/success |
| 3 | 字段说明 10.5px 用 0.36 墨 = 2.35:1，低于 4.5:1 底线，而用户是明亮车间的一线人员 | 说明行改用 `text.secondary`（0.62 墨 ≈ 5.33:1）；`text.disabled` 顺带从 0.36 提到 0.45 |
| 4 | 方向卡面承诺的裁切线/色标条默认全关且开关藏在折叠里，首屏纸面看不到任何印刷标记；出血没有参数也没有实现 | 裁切标记改为**默认打开**（标记本来就该印在纸上）；「印刷标记」从「更多规格」折叠提到二维码段常显；出血不实现——白底标签没有满版覆盖，画一条出血线是装饰，按「不加没有实现支撑的承诺」处理 |
| 5 | 批量表回退分支把「未知跨度」算成「第 1–1 条」，与注释和纪律都相反 | `readVisibleSpan` 拿不到渲染上下文时返回 `null`，表头只报「共 N 条」，不再输出一个具体的、错的区间 |
| 6 | `PRODUCT.md` 栈口径仍写「包管理器 npm」，与 `bun.lock` 现实相左 | 改为 bun 口径（含命令与锁文件） |

- 已知限制：
  - 本机的无头 Chromium 在批量视图下 `Page.captureScreenshot` 会挂起，`batch.png` 未能落盘；批量面改用上表的尺寸与读数测量作为证据，视觉部分在会话内直接看过。
  - 移动端预览尺寸仍受竖屏高度限制（现为 226×320 px 的印张），这是「参数塌缩但印张与导出永不被挤掉」的取舍。
  - 设计系统侧记：`DESIGN.md` 记录了 4 条「不作为房子风格继承」的既有瑕疵（未消费的字号变体、一处死 `borderColor`、三档近乎相同的墨阶、界面色与印制过程色是两套配方），本次未修，留待需要时收敛。
