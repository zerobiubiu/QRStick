# 0011 · 批量「单张突出」滚轮换张与预览提示

- 状态：已执行
- 影响范围：`src/components/PressSheet.tsx`、`src/components/BatchPreviewGrid.tsx`
- 前置文档：[0010-批量预览统一为-PressSheet.md](0010-批量预览统一为-PressSheet.md)
- 生效版本：**0.5.1**（补完 0.5.0 已声明的「网格/预览交互」同一族能力 → patch）

## 背景

批量「单张突出」里逐张检查 40 行时，换张只能点工具栏的「‹ 上一张 / 下一张 ›」：每次都要把指针从纸面移到按钮上，按键本身只有 22px 高。指针本来就停在印张上，滚动是最自然的换张手势。

但台面（`PressSheet` 的 stage）在放大态是**可滚动容器**（×1.5 及以上 `overflow: auto`），滚轮在那里已经有用（滚纸面）；而 React 的 `onWheel` 是挂在根上的**被动监听**，`preventDefault()` 无效——想「换张时不带动页面一起滚」就不能走 React 合成事件。

## 方案

| 项 | 做法 |
| --- | --- |
| 接管条件 | 只在**台面滚不动**时（`scrollHeight <= clientHeight + 2`，即适应态）接管滚轮；放大到台面可滚时滚轮仍先滚纸面，不抢已有手感 |
| 原生非被动监听 | 在台面节点上 `addEventListener('wheel', handler, { passive: false })`，换张时 `preventDefault()` 阻止页面跟着滚；React 合成事件做不到这点 |
| 一格一张 | 累计量放 ref：`|累计| >= WHEEL_STEP_PX(40)` 才切一张并归零。Windows 一格滚轮 100–120 → 正好一张；触控板一格只有几像素 → 小步累计够 40 才换，避免一次飞过头 |
| 不设空闲定时器 | 原设计有 220ms 空闲重置，但它依赖 `setTimeout`——隐藏/无头标签页里计时器被钳到 ≥1s，行为随标签页可见性变化。改为「够一格就换并归零」，不引入时间维度；残留（< 40）只会让下一次手势多滚一点点，**不可能造成多换** |
| 回调走 ref | `onStep` 的依赖链里有 store（每次渲染都是新对象）→ 放进 effect 依赖会让监听器反复重建、累计量被清空（实测现象：阈值时灵时不灵）。监听器只挂一次（deps `[]`），最新回调经 `onStepRef` 读取 |
| 不循环 | 复用既有的 `step()`（已对首/末行钳位），滚轮与按钮行为一致 |
| 提示 | 单张突出工具栏补一行「滚轮切换上下张」（窄屏 `display: none`，避免挤掉按钮） |

`PressSheet` 的 `onStep` 是**可选** prop：只有批量「单张突出」传它；单张制作模式没有「上下张」，不传即保持原样（滚轮在那里照旧滚页面）。

## 执行验证记录

- 执行环境：Windows 10.0.26300；bun 1.4.2；Chromium（headless，1440×900）；`bun run dev`（Vite 8.3.4）。
- 验证动作与实际输出：

| 动作 | 实际输出 | 结论 |
| --- | --- | --- |
| `bunx tsc -b` / `bun run lint` / `bun run build` | 0 错误；1 条既有警告（`src/lib/download.ts:53` 控制字符正则）；`✓ built in 649ms` | 检查通过 |
| 真实滚轮（CDP `Input.dispatchMouseEvent`，适应态，指针停在纸面） | 第 1 行 `+120` → **2**，`-120` → **1**；末行 `+120` → 仍是末行 | 下/上各换一张，且首末不循环 |
| 真实滚轮一次大幅（`+200`） | 只换 **1** 张 | 一次手势只换一张 |
| 真实滚轮 ×3 放大态 | 行号 **不变**（4 → 4），台面 `scrollTop` **0 → 120** | 放大态滚轮仍在滚纸面，未被劫持 |
| 合成 wheel 事件（时间与增量完全受控，适应态重置后） | `1×15` → +0；`1×40` → +1；`4×12`（间隔 30ms，累计 48）→ +1；`2×10`（累计 20）→ +0；`3×15`（间隔 250ms，累计 45）→ +1；`6×12` 连发（72）→ 只 +1 | 阈值、累计、一次一张全部符合设计 |
| 页面自身滚动 | 换张时 `window.scrollY = 0`（`preventDefault` 生效） | 换张不带动整页 |

- 探针自身的坑（都已定位并修正，记录以免误导后续排查）：
  1. `page.mouse` 写在 `page.evaluate` 内 → `ReferenceError`；鼠标动作必须在 `tab.run` 作用域里发。
  2. 一次抓取 `.sheet-ink` 节点后反复派发事件 → 该节点带 `key={signature}`，**换行时会被 React 替换成新节点**，旧变量指向脱离文档的节点，表现为「只有第一次生效」；应每次现取活节点。
  3. 上一条用例把缩放留在 ×3 → 台面可滚 → 处理器**按设计拒绝**接管滚轮，表现像「功能坏了」；验证前必须复位到「适应」。
  4. 合成用例之间累计量残留（去掉空闲重置后累计跨手势保留）→ 反向用例 `3×15`（45）被上一条残留的 +24 抵消成 −21，未换张。这是**测试串扰**：残留恒 < 40，永远不足以自行换张，只会让该次手势多滚一点。
- 已知限制：
  - 阈值 40px：一格鼠标滚轮（100–120）稳定换一张；触控板需要累计到 40px 才换一张（设计如此）。
  - 首末行不循环（与按钮一致，不做「撞到边界反向」）。
  - 监听器只在挂载时绑一次；台面节点（stage Box）无 key、不会在换张时被替换，故绑定长期有效（已由「多次换张后滚轮仍生效」验证）。
  - 触屏没有 wheel 事件，移动端仍走按钮。
  - 边界抖动：`scrollHeight > clientHeight + 2` 作为「台面可滚」的判据，恰好在临界尺寸（差 1–2px）时可能随窗口微调在「接管/不接管」间跳变。

## 后续验证建议

- 真机复核手感：鼠标滚轮连续快速滚动（多行连跳）与触控板慢滚（累计到阈值才换）是否符合直觉；必要时把 `WHEEL_STEP_PX` 从 40 上调。
- 复核 ×1.5 且纸面刚好吃满台面时（`scrollHeight ≈ clientHeight`）滚轮的接管边界是否稳定。
