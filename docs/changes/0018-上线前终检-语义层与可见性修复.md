| # | 发现 | 证据 | 判定 |
| --- | --- | --- | --- |
| 1 | **全站没有任何标题、5 个 `section` 无标签、印张画布无替代文本** | `h1–h6` 计数 0；`section[aria-label]` 计数 0；canvas 的 `role/aria-label/alt` 全为 null | 语义缺失（读屏只能一路 Tab 过约 25 个控件） |
| 2 | **套准十字的三条色版臂与印张底色是裸色值** | `stroke="#0093d0" / "#e5007d" / "#ffe200"`、`bgcolor: '#fff'` | 0017 漏掉的颜色令牌（青色/品红/黄色在 theme 里早有导出） |
| 3 | **空内容占位框在预览里细到看不见** | 按 `max(1, dpi/300)` 画，缩到预览后可见线宽约 0.4px | 这是「内容为空」唯一看得见的状态，反而最不明显 |
| 4 | **批量导出的文件名取自单张态的标题** | `run.ts` / `runImage.ts` 都用 `config.title.text` 起名（实测 6 行数据得到「库位 A-03-12-6张.pdf」，而页面标题是别的） | 误导性文件名 |
| 5 | `DESIGN.md` 关于「禁用墨 0.45」的用途说明过期 | 代码里 `0.45` 只剩 MUI 的 `text.disabled`，批量数据源的折叠提示早已不用它 | 台账准确性（顺带把「0.45 不承载可读信息」写成规矩） |

## 方案

| 项 | 做法（窄处最小正确层） |
| --- | --- |
| 语义层 | 站名 `Typography component="h1"`；分段小标题 `component="h2"`（**视觉零变化**：字号/字重/外边距不动，只换标签）；段容器 `section aria-label={title}`；批量数据源段、工单列、印张列各给 `aria-label`；印张画布宿主 `role="img"` + 一句版面摘要作替代文本 |
| 裸色值 | 套准十字三臂改用 `theme.ts` 的 `CYAN / MAGENTA / YELLOW`；印张底色改 `var(--paper)` |
| 占位框 | 线宽 `max(2, round(dpi/150))`（300 DPI → 2 导出像素），缩到预览也有约 2px 可见 |
| 导出文件名 | 批量时用**第一行**的标题作基准（`batchConfigs[0] ?? config` / `targets[0] ?? config`），单张态不变 |
| 台账 | `DESIGN.md`：0.45 的说明改成「MUI 的 text.disabled，不承载可读信息」；补三条新事实（分段标题是 h2、画布 role=img 与替代文本、占位框线宽下限）；顺带清掉 0016 去行号后残留的 **28 处悬空相对行号片段**（如 `:198-199`） |

**明确不做**：刻度尺数字标签的固定 2.5px 右移（快照的小观察）——本轮在构建产物里实测，默认密度（≈2.2 px/mm）与 ×3 缩放下读数都清楚，只有在极低密度（窄屏适应）才可能歧义，而那时刻度本就属装饰性；改它要动刻度几何，收益小于风险。滑杆量程窄于数字框是 0001 决策的刻意取舍（DESIGN.md 有记），仍不动。

**已知限制**：

- 语义层只做到「标题 + 地标 + 画布替代文本」：表格仍是 MUI 的 `role=grid`（未加 `<caption>` / `aria-rowcount`）；体检条目仍以线型为主，读屏听到的是消息文本本身（不含「错/警」二字）——要加需要在标记上挂 `aria-label`，本轮没做。
- 刻度尺数字标签的固定 2.5px 偏移保留（理由见上）。
- 本轮改动面 7 个文件、且是纯语义/小数值修改，验证靠 tsc/lint/test/build/detect + 上述构建产物实测兜底（未跑 axe 等额外工具；reference 也要求「不要再加一遍探测器」）。

## 后续验证建议

1. 若要继续补无障碍：给批量表加 `<caption>`，给体检标记挂 `aria-label="错误/提醒"`，给读数条设成定义列表（`dl`）——三处都是纯语义、零视觉变化。
2. 换密度（窄屏 390×844）复查刻度标签是否会歧义；若确实会，把标签偏移改成随 `pxPerMm` 缩放。
3. 每次发布前跑一遍这套：`tsc` / `lint` / `bun test` / `build` / `detect` + 构建产物上的「语义盘点 + 一次键盘走查」。
