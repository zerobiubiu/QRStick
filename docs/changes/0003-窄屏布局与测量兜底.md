# 0003 · 窄屏布局与台面测量的兜底

- 状态：已执行
- 影响范围：`src/App.tsx`、`src/components/PressSheet.tsx`
- 前置文档：[0001-初版实现.md](0001-初版实现.md)
- 生效版本：0.1.0（未发布前的同版本修复）

## 背景

初版提交后，用真实浏览器在 1440 / 1180 / 390 三个宽度上检查时发现三类问题：

1. **窄屏印张不见了**：`xs` 布局里印张所在网格行是 `auto`，内部又靠 `flex: 1` 分高度，结果量到的台面尺寸是 0，渲染核的「台面小于 0.4 px/mm 就不画」判断直接把印张跳过了。
2. **窄屏批量表塌成 0 高**：同一类问题——单列 auto 行 + 虚拟列表需要明确高度。
3. **窄屏整体横向溢出**：读数条在窄屏换行成三行，把网格列撑到 819 px（视口只有 390 px），整页横向滚动；读数条还把印张挤到只剩 151 px 宽。
4. **量尺寸只在首帧有效**：`ResizeObserver` 在某些无头/隐身环境下不投递回调（本地实测确实没投递），窗口尺寸变化后台面尺寸不更新，印张一直停在旧尺寸。

## 方案

- **给需要高度的东西明确高度**：窄屏下印张容器 `58dvh`、批量表 `38dvh`、批量预览块 360 px；桌面端继续用 `flex: 1` 分配剩余空间。
- **读数条按优先级塌缩**：窄屏 `flex-wrap: nowrap` + `overflow-x: auto`，读数压成一行横滑，绝不挤占印张。
- **网格轨道可收缩**：`grid-template-columns: minmax(0, 1fr)` 并在两列容器上加 `min-width: 0`，禁止内容把列撑宽。
- **量尺寸三重保险**：挂载即量（`getBoundingClientRect`）+ `ResizeObserver` + `window.resize` 监听与一次 `requestAnimationFrame` 补量；0 尺寸一律忽略，避免瞬时的 0 高度把印张抹掉。
- **画布用 ref 回调挂载**：节点可能出现在首次测量之后，用 `useEffect` 会漏挂。

## 实施（改动文件清单）

| 文件 | 改动 |
| --- | --- |
| `src/App.tsx` | 窄屏印张/批量表/预览块的明确高度；`minmax(0, 1fr)` 与 `minWidth: 0` |
| `src/components/PressSheet.tsx` | 三重测量兜底 + 0 尺寸忽略 + 回调 ref 挂画布 + 读数条窄屏横滑 |

## 执行验证记录

- 执行环境：Windows 10.0.26300；bun 1.4.2；Chromium（headless）；`bun run dev`。
- 验证命令与实际输出：

| 动作 | 实际输出 | 结论 |
| --- | --- | --- |
| `bunx tsc -b` / `bun run build` | 0 错误；`✓ built in 813ms` | 类型与构建通过 |
| 视口 1440×900 | 印张 533×754，台面 1036×768，`scrollWidth == clientWidth` | 桌面正常 |
| 视口 1180×820 | 印张 448×634，台面 776×648 | 中间宽度正常 |

- 已知限制：窄屏印张偏小（竖屏高度受限），属于预期取舍——保证「印张与导出永远不被挤掉」，其余参数滚动查看。
